# OrderRoom 画面仕様

更新日: 2026-07-22

この資料は画面ルート、画面責務、表示状態、モックUI、画面受け入れ条件を管理する。MVP範囲と実装順は[ロードマップ](ロードマップ.md)、権限は[MVP仕様](MVP.md)を優先する。

## 1. この資料と現行FE実装の扱い

画面の将来仕様はこの資料を正とする。ただし、実装状況は `frontend/src` の現行コードに合わせて記録する。

2026-08-03時点で実装されているルートは `/`、`/create`、`/join`、`/rooms/:roomId` である。

- `/join` は表示名とURL/伝票番号を入力する暫定画面であり、参加APIには未接続である。
- `/rooms/:roomId` は存在するが、URLのroomIdを使ったルーム情報取得、表示名参加、商品API接続は未実装である。
- 確定仕様では参加者が共有URLを直接開くため、参加導線は `/rooms/{roomId}` に寄せる。
- 現在の画面UIはモックUI中心であり、API接続、データ保存、権限判定、別端末同期は未完成である。
- 実装差分の詳細は[実装照合レポート](実装照合レポート.md)、動作リスクは[動作リスク仕様](動作リスク仕様.md)を参照する。

## 2. 現在の実装状況

| 画面 | 現行ルート | 現在の実装 | 次の対応 |
| --- | --- | --- | --- |
| トップ | `/` | 作成・参加への遷移。伝票風の見出しと罫線を表示 | 文言を「提案」中心へ統一し、共有URL参加へ導線を変更 |
| ルーム作成 | `/create` | 日付、ルーム名、メモ、予算入力欄あり。ただし作成ボタンはAPIではなく`/rooms/test-123`へ遷移 | 作成APIへ接続し、レスポンスの`id`で遷移する。予算を実装するか一時的に外す |
| 暫定参加 | `/join` | 名前、URL/伝票番号の入力。参加時はconsole出力 | MVPでは`/rooms/{roomId}`の参加前状態へ寄せる。参加コード方式を採用する場合のみ再利用候補 |
| 作成成功 | なし | 未実装 | 参加URLコピー、ホストURL警告、hostKeyのsessionStorage移行を実装 |
| 参加・通常ルーム | `/rooms/:roomId` | モックUIあり。URLのroomId、ルーム取得、参加API、商品APIには未接続 | 参加、提案、一覧、手動更新をAPI接続する |
| ホスト管理 | なし | 未実装 | `/rooms/{roomId}/host?key=...`ルート、幹事参加、幹事提案、採用、今回は見送る、提案中に戻す、編集・削除、購入済み操作を実装 |
| 買い物・集計 | なし | 未実装 | accepted一覧、見積・予算集計を実装 |
| 割り勘・精算 | なし | 未実装 | 統合MVPで実装 |

## 3. デザイン方針

現行FEの紙色、罫線、伝票風の見出しを維持し、次の方針を適用する。

- ベージュの紙、黒い罫線、赤い印章を使った伝票表現を維持する。
- モバイル中心の1カラムとし、375px幅で本文を12px未満にしない。
- 色だけで提案中、採用、見送りを区別しない。
- UI文言は「注文」ではなく「提案」、「却下」ではなく「見送り」を使用する。
- room-pageの提案フォームは、商品名、見積単価、数量を主入力とし、メモはボトムシート形式で確認・編集する現行FE案を前提にする。ただしAPI未接続のため、永続化までMVPへ含めるかはPMとFE/BEで判断する。

## 4. 確定ルートと実装段階

| 画面 | 確定ルート | 利用者 | Slice | 実装段階 |
| --- | --- | --- | --- | --- |
| トップ | `/` | 全員 | 既存土台 | モックUIあり |
| ルーム作成 | `/create` | ホスト | 1 | モックUIあり。API結合は未完成 |
| 作成成功 | `/rooms/{roomId}/created` | ホスト | 1 | 未実装 |
| 参加・通常ルーム | `/rooms/{roomId}` | 参加者 | 1〜2 | モックUIあり。API結合は未完成 |
| ホスト管理 | `/rooms/{roomId}/host?key=...` | ホスト | 3〜4 | 未実装 |
| 買い物 | `/rooms/{roomId}/shopping` | 全員 | 3・5 | 未実装 |
| 割り勘・精算 | `/rooms/{roomId}/settlement` | 全員 | 5 | 未実装 |

参加前と参加後は `/rooms/{roomId}` 内で、ルーム単位のparticipant tokenの有無により切り替える。汎用 `/join` は新規実装の基準にしない。

### Phase2候補: 参加コード・ホスト承認

GitHub Discussionsでは、参加者が短い参加コードを入力する方式と、ホスト承認後に参加確定する方式が提案されている。採用する場合は次の画面が追加で必要になる。

- 参加コード入力画面。現行の暫定`/join`を再利用するか、新規ルートにするかを決める。
- 参加リクエスト送信後の申請中画面。
- ホスト向けの参加申請一覧、承認、却下UI。
- 承認結果を参加者が確認する導線。リアルタイム同期を使わない場合は手動更新またはポーリングを検討する。

MVPでは共有URLから表示名だけで参加する導線を優先し、参加コード・ホスト承認は確定ルートへ含めない。

## 5. モックUIの扱い

- API未接続の画面は、仮データを使って操作、画面遷移、表示状態を確認する。
- モックUIでは、認証、URL共有、データ保存、別端末同期は完了扱いにしない。
- API接続時に置き換えるデータ型、成功レスポンス、エラーレスポンスをFEとBEで確認する。
- 状態は「未着手」「モックUI」「API実装済み」「結合済み」「受け入れ確認済み」で区別する。

## 6. 共通状態

| 状態 | 表示と操作 |
| --- | --- |
| 読込中 | 読み込み中と分かる表示を出す |
| 空 | 次に行う操作を説明する。例: 「まだ提案がありません」 |
| 通信失敗 | 原因を断定せず、再試行ボタンを出す |
| 404 | ルームが見つからないことと、トップへ戻る導線を出す |
| 403 | 操作権限がないことを示し、通常画面へ戻せるようにする |
| 入力不正 | 該当欄の近くに修正方法を出す |
| 送信中 | 二重送信を防ぎ、完了または失敗まで状態を維持する |

## 7. 画面別仕様

### 7.1 トップ

- 「ルームを作る」を主操作にする。
- MVPではルーム一覧を置かない。
- 参加者は共有URLから参加するため、伝票番号や参加URLを手入力する導線は置かない。

### 7.2 ルーム作成

入力:

- イベント名 `title`: 必須
- 開催日 `eventDate`: 任意
- メモ `memo`: 任意
- 予算上限 `budgetAmount`: 任意、0円以上

状態:

- 必須項目エラー
- 金額形式エラー
- 送信中
- API失敗と再試行

### 7.3 作成成功

- ルーム名を表示する。
- 参加URLをコピーでき、コピー完了を表示する。
- ホストURLを参加URLと分けて表示する。
- ホストURLへ「共有しない」警告を出す。
- hostKeyを通常本文へ繰り返し表示しない。
- 「参加者画面を開く」「幹事画面を開く」を区別する。

### 7.4 参加・通常ルーム

参加前:

- ルーム名と開催日を表示する。
- 表示名だけ入力する。
- ログインやURL再入力を要求しない。

参加後:

- 商品名、見積単価、数量、メモを提案できる。
- 提案者名と状態を一覧表示する。
- 自分の提案だけ編集・削除操作を表示する。
- 編集対象は商品名、見積単価、数量、メモに限定する。
- 編集をキャンセルした場合は元の内容を保持する。
- 削除前には確認を出す。
- 他人の提案には編集・削除操作を表示しない。
- 手動更新と最終更新時刻を表示する。
- rejectedは通常一覧で非表示にする。

### 7.5 ホスト管理

- 幹事モードであることを常に表示する。

#### 参加者としての幹事

- 幹事自身が参加者として表示名を登録できる導線を用意する。
- 幹事が参加者登録済みの場合、幹事画面からも商品名、見積単価、数量、メモを提案できる。
- 自分の提案を編集・削除できる。

#### 管理者としての幹事

- 幹事が参加者登録しても、採用、今回は見送る、提案中に戻す、購入済み変更の管理権限は維持する。
- proposedには採用、今回は見送る操作を出す。
- acceptedには今回は見送る、提案中に戻す、購入済みにする、未購入に戻す操作を出す。
- rejectedには採用、提案中に戻す操作を出す。
- rejectedを確認できるフィルタを用意する。
- 全提案を編集・削除できる。
- 編集対象は商品名、見積単価、数量、メモに限定する。
- 編集キャンセル時は元の内容を保持する。
- 削除前には確認を出す。
- acceptedの商品だけ購入済みに変更できる。
- 状態変更、購入済み変更、編集、削除後は一覧、採用済み合計、提案中見積、予算との差額を即時更新する。
- 管理URLの共有禁止警告を確認できる。
- tokenやhostKeyを画面本文へ出さない。

### 7.6 買い物・集計

- acceptedだけを表示する。
- 商品別数量を表示する。
- ホストだけが購入済みを変更できる。
- 採用済み見積を最も目立つ位置へ出し、提案中見積を補助表示する。
- 予算がある場合だけ残額または超過額を表示する。
- rejectedを集計に含めない。
- 「合計金額」だけで意味を省略しない。

### 7.7 割り勘・精算

- 精算対象者を選択する。
- 実購入額合計、参加者別の負担額、立替額、差額を表示する。
- 「AさんからBさんへ○円」の形式で送金案を表示する。
- 参加者は自分が支払側の精算だけを精算済みにでき、ホストは全件を操作できる。
- 精算済みがある場合、計算元がロックされていることを説明する。
- ホストのリセットには確認ダイアログを出す。
- 未入力商品、精算対象者0人、計算失敗を区別して表示する。

## 8. 画面受け入れ条件

### モックUI

- 仮データで作成、作成成功、参加・通常ルーム、ホスト管理の画面遷移と主要状態を確認できる。
- 参加者とホストで操作できる内容の差が画面から分かる。

### API結合

- 作成後に参加URLをコピーできる。
- ホストURLは作成者だけに表示する。
- 共有URLを直接開いてルーム名を確認できる。
- 表示名だけで参加できる。
- hostKeyなしでは採用、今回は見送る、提案中に戻す、購入操作ができない。
- 幹事自身が参加者として登録し、幹事画面から提案を追加できる。
- 提案者本人、幹事、第三者で編集・削除できる範囲が異なることを確認できる。
- 編集、削除、採用、見送り、提案中へ戻す、購入状態変更後に一覧と合計が即時更新される。

### 集計・精算

- 採用済み見積、提案中見積、実購入額、負担額を区別できる。
- 予算未入力時は予算差分を表示しない。
- 実購入額と購入者が揃わない商品を精算対象にしない。
- 精算済み権限とロック状態を画面から理解できる。

### 実機

- iPhone Safariで直接URL、コピー、フォーム、再読込を確認する。
- 375px、390px、430pxで横スクロールなしに主操作を完了できる。
- MacとiPhoneの2端末で手動更新による反映を確認する。
- ローカル起動で、幹事作成 → 幹事参加 → 提案追加 → 編集 → 採用 → 購入済み → 削除までを確認する。
