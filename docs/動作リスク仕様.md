# OrderRoom 動作リスク仕様

更新日: 2026-08-03

この資料は、現在の仕様・docs・実装のずれにより、アプリが動かない、または結合時に壊れる可能性がある項目をまとめる。修正優先度は「作成 → 参加 → 提案 → 一覧」のE2E導線を最優先にする。

## 優先度

| 優先度 | 意味 |
| --- | --- |
| P0 | 現在のままだと主要導線が動かない可能性が高い |
| P1 | 一部機能が仕様通りに動かない、または後続実装を阻害する |
| P2 | MVP後候補、または今すぐは動作阻害しないが整理が必要 |

## P0: 主要導線が動かない可能性

| 項目 | 現状 | 起きること | 対応案 |
| --- | --- | --- | --- |
| ルーム作成ボタンがAPIを呼ばない | `CreatePage`の作成ボタンは`navigate('/rooms/test-123')`固定 | 実DBにルームが作られず、存在しないroomIdへ遷移する | ボタンの`onClick`を`handleCreate`へ変更する |
| ルーム作成APIのレスポンスキー不一致 | FEは`data.roomId`を参照するが、BEの`CreateRoomResponse`は`id` | API接続しても`/rooms/undefined`へ遷移する可能性 | FEは`data.id`を使う、またはBEレスポンスに`roomId`を追加する |
| `Content-Type`ヘッダー不正 | FEの`handleCreate`が`'Content-Type':'/application/json'`を指定 | APIがJSONとして扱えず400/415になる可能性 | `application/json`へ修正する |
| `budgetAmount`の仕様と実装が不一致 | FEに予算入力欄、docsに仕様あり。BEの`Room`/`CreateRoomRequest`にはなし | 予算が保存されず、予算差分も計算できない | 実装するか、MVPから一時的に外すか決める |
| `GET /api/rooms/{roomId}`が未実装 | docsと画面仕様では共有URL表示に必要だがControllerにない | `/rooms/{roomId}`を開いてもルーム名・開催日を取得できない | BEにGETを追加し、FE RoomPageでfetchする |
| RoomPageがURLの`roomId`を使っていない | `RoomPage`は固定表示とローカルstateのみ | 共有URLや別端末参加が成立しない | `useParams`で`roomId`を読み、API接続する |
| 表示名参加がFE未接続 | BE参加APIはあるがFEから呼んでいない | participant tokenが取得・保存されず、商品提案者を確定できない | `/rooms/:roomId`で参加APIを呼び、tokenをlocalStorage保存する |
| 商品提案がFE/BE未結合 | FEはlocal stateだけ、BE APIはある | 再読込・別端末で提案が消える | 商品作成・一覧APIへ接続する |
| 外部DB接続情報が未設定だとBE起動不可 | `DB_URL/DB_USER/DB_PASSWORD`必須 | `.env`がない/値が違うとSpring起動時にDB認証エラー | `.env`を正しく設定する。テスト用DBまたはローカルDBも検討する |

## P1: 仕様通りに動かない可能性

| 項目 | 現状 | 起きること | 対応案 |
| --- | --- | --- | --- |
| 商品作成の本人確認方式が仕様と違う | docsは`X-Participant-Token`、BEは本文`participantId` | 他人のparticipantIdで商品作成できる可能性がある | tokenからparticipantを特定する方式へ変更する |
| participant tokenをFEが保存しない | BEは参加時にtokenを返すがFE未利用 | 自分の提案編集・削除、参加者本人操作が実装できない | `orderroom.participantToken.{roomId}`形式で保存する |
| hostKeyをFEが保持しない | BEはhostKey発行・検証あり、FE host画面なし | ホスト操作UIから採用・見送り・提案中へ戻す・購入済み変更ができない | 作成成功画面でhostKeyをsessionStorageへ移す |
| hostルートが存在しない | docsは`/rooms/{roomId}/host?key=...`、FEルートなし | hostUrlを開いても画面がない。幹事自身の参加者登録と提案追加もできない | host画面ルートを追加し、幹事参加導線を用意する |
| 集計APIの意味がdocsと違う | BE summaryはrejected以外を合算 | accepted合計、proposed補助合計、予算差分が表示できない | summaryレスポンスをdocsに合わせる |
| accepted編集時の再承認仕様が未実装 | 商品内容編集API自体がない | accepted編集でproposedへ戻す動きが存在しない | 編集API実装時にstatus/purchased更新ルールを入れる |
| 商品削除APIがない | FEの削除はローカルのみ | DB上の商品を削除できない。削除前確認や削除後の合計更新も永続化されない | `DELETE /items/{itemId}`を実装し、提案者本人・幹事・第三者の権限を分ける |
| 状態変更後の即時集計更新が未接続 | FEはAPI一覧・summaryに未接続 | 採用、見送り、提案中へ戻す、購入済み変更後に表示合計が古いままになる | 操作成功後に一覧とsummaryを再取得するか、同等のローカル更新を行う |
| 実購入額・購入者が未実装 | docsにはあるがEntity/APIにない | 統合MVPの精算導線が作れない | `actual_price`、`paid_by_participant_id`とAPIを追加する |
| 精算モデルが未実装 | docsにはsettlementがあるがコードなし | 統合MVPの後半が動かない | Entity/API/画面を新規実装する |

## P2: 方向転換提案・MVP後候補

| 項目 | 現状 | リスク | 対応案 |
| --- | --- | --- | --- |
| 参加コード方式 | 未実装。`/join`は暫定画面のみ | MVP中に採用するとURL参加仕様、DB、API、FE導線が変わる | Phase2 Issueに切り出す |
| 6文字コード + ホスト承認制 | 未実装 | 即時参加のMVP要件と衝突する。承認待ち・承認UI・状態確認が必要 | MVP後に別設計として扱う |
| item memo削除/別レイアウト | BEにはmemoあり、FEにはボトムシート形式のメモ確認・編集UIがある。ただしAPI未接続 | docsとUIの方向性は概ね一致したが、保存先がlocal stateのみなので再読込・別端末で消える | memoをAPI接続するか、MVPではローカルUI扱いに留めるか決定 |
| hostKeyをURLに残さない | docsでは推奨、FE未実装 | URL共有ミスや履歴に秘密値が残る | 作成成功/host画面実装時にsessionStorageへ移す |

## 最短で動く状態にするための順番

1. BEの`POST /api/rooms`とFEの`CreatePage`を接続する。
2. `GET /api/rooms/{roomId}`をBEに追加し、`RoomPage`で取得する。
3. `POST /api/rooms/{roomId}/participants`をFEに接続し、tokenを保存する。
4. 商品作成を`X-Participant-Token`方式へ寄せる、または一時的にdocsへ実装差分を明記した上でparticipantId方式を使う。
5. 商品一覧をFEに接続し、再読込・別端末で表示できるようにする。
6. hostKeyを使うホスト画面を追加し、status/purchased操作を接続する。
7. accepted/proposed/予算差分の集計仕様をBE/FEで合わせる。

## 採用してはいけない混ぜ方

- MVP中に「共有URL参加」と「参加コード+ホスト承認」を同時に進めない。導線、API、状態管理が分岐して完成判定が曖昧になる。
- `participantId`本文指定のまま、自分の提案編集・削除を実装しない。本人確認が弱くなる。
- 予算差分を画面に出す前に、BEに`budgetAmount`を保存しない。画面だけの値になり、再読込で消える。
- hostKeyを通常一覧レスポンスやログに出さない。ホスト権限と参加コード/参加URLを混同しない。
